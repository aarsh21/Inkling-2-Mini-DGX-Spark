| TokenSpeed | `lightseekorg/tokenspeed:nightly-c47e7a` (2026-11-16) rebuilt at lightseekorg/tokenspeed#3682 head `52fdeee2` (`engines/tokenspeed/build.sh`) | The newest published image predates Inkling 2 Mini (no `Inkling2LoopForConditionalGeneration`); support is an open PR whose kernels were validated on AMD gfx950. The PR sits 156 commits after the image, and copying only its Python over the image fails at startup (`ModuleNotFoundError: No module named 'tokenspeed_engine.scheduler'`): the runtime needs the newer engine. `build.sh` therefore builds the engine wheel (Rust `ts-host` + C++ scheduler) from the PR, overlays the PR's kernel Python compiles tokenspeed-kernel for sm_121a (the image ships only sm_90a/100a/103a kernels: "no kernel image is available"), applies `sm12x-skinny-mm.patch` (one Triton GEMM needs 147 KB of shared memory; GB10 has 99 KB) and installs the PR's `tokenspeed` package. It serves at 32 requests and 64K context (64 at 262K leaves a pool that "cannot admit one token"), at about a third of vLLM's speed. |
| llama.cpp (mainline) | b12600 (`29b52d39`, ggml-org/llama.cpp#32694) release binaries on `ghcr.io/ggml-org/llama.cpp:server-cuda13` `sha256:c5576f106d1e…` | The published server-cuda13 image (2026-11-17) fails with `unknown model architecture: 'inkling2_loop'`, so `build.sh` puts the b12600 binaries on its runtime. Serves `ggml-org/Inkling-2-Mini-GGUF` IQ4_NL. Its `draft-dspark` drafter refuses Unsloth's DSpark GGUF (`markov_w1.weight` has wrong shape: expected 256 x 200058, got 256 x 201024), and Unsloth notes mainline still lacks #32704 for looped NVFP4 scales, so it runs without speculation and is gated on GSM8K. |
| llama.cpp (Unsloth fork) | `unslothai/llama.cpp` b12588-mix-c0c3de8 (`88328607`), arm64 CUDA 13 portable build (sm_90-sm_121), same runtime image | Serves Unsloth's root `UD-Q4_K_XL` GGUF (Unsloth's looped layout) with its DSpark drafter (`dspark-Inkling-2-Mini-Q8_0.gguf`), the combination Unsloth documents. |
| TensorFold | `ashhart/TensorFold` `e3efa80e` (2026-11-21) | **Cannot serve Inkling 2 Mini yet.** The `inkling2` family has a host package and attention kernels for Inkling 2 Small only; nothing serves it ("nothing serves it yet", CHANGELOG), there is no loop support, and Mini is a plan document in an open PR (ashhart/TensorFold#4274, "a plan for Inkling 2 Mini on CUDA and Metal in claimable slices"). Kernel PRs #4126-#4128 are open. |
